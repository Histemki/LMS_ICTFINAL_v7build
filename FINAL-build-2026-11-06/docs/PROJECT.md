# LMS университета: документация проекта

Учебная платформа (редизайн Moodle университета) для трёх ролей: **студент**, **преподаватель**, **администратор** (Registrar Office).
Один Flask-сервер на Python, база PostgreSQL, фронтенд без сборки: одна страница `index.html` с обычным JavaScript.

## 1. Быстрый старт

### Что нужно
- Python 3.10+ и PostgreSQL.
- Пустая база данных (например `lms_db`). Сервер сам создаёт таблицы и демо-данные при первом запуске, но саму базу не создаёт.

### Запуск
```bash
pip install -r requierments.txt
```
Имя файла именно такое, с опечаткой: `requierments.txt`. В нём `flask`, `psycopg2-binary`, `bcrypt`, `segno` (рисует QR-код; без него преподаватель видит только текстовый код).

Задайте строку подключения к базе (по умолчанию `postgresql://postgres:YOUR_PASSWORD@localhost:5432/lms_db`):
```powershell
$env:DATABASE_URL = "postgresql://postgres:ПАРОЛЬ@localhost:5432/lms_db"
python app_postgresql.py
```
Открыть: <http://127.0.0.1:5000>

### Демо-аккаунты
Создаются при первом запуске на пустой базе. Пароль у всех один: значение `DEMO_PASSWORD` (по умолчанию `Lms#2026demo`).

| Роль | Логин | Примечание |
|---|---|---|
| Студент | `260002@astanait.edu.kz` ... `260101@astanait.edu.kz` | 100 студентов, у каждого 5 случайных курсов |
| Преподаватель | `teacher@astanait.edu.kz` (Diana Kazbekova) | ведёт курс 1 (ICT). Остальные: `a.sarsenov@`, `m.omarova@`, `e.tulegenov@`, ... (полный список в `TEACHERS`, `app_postgresql.py`) |
| Администратор | `admin@astanait.edu.kz` | Registrar Office |

10 демо-курсов: ICT, Databases, Calculus, Physics, English, Algorithms, Web Development, Statistics, Discrete Math, Networks (коды `CSE101`...`CSE110`). Преподаватель курса №N это N-й в списке `TEACHERS`.

> Перед настоящим использованием смените `DEMO_PASSWORD`, задайте `CHECKIN_SECRET` и отключите демо-режим (`APP_ENV=production`).

### Запуск без PostgreSQL (только посмотреть интерфейс)
Тестовый сервер с заглушками, настоящая база не нужна:
```bash
python tools/mock_server.py . 5000
```
> **Не запускайте тестовый сервер и настоящий одновременно.** Оба используют порт 5000, а Windows позволяет занять его дважды, поэтому запросы уйдут в тестовый сервер, который **пускает с любым паролем**. Перед запуском `app_postgresql.py` убедитесь, что порт свободен: `Get-NetTCPConnection -LocalPort 5000 -State Listen`.

Входы: `260002@astanait.edu.kz` (студент), `teacher@astanait.edu.kz` (преподаватель), `admin@astanait.edu.kz` (администратор), пароль любой. Данные в памяти, после перезапуска сбрасываются. Это инструмент для проверки интерфейса, настоящие правила и SQL он не проверяет.

```

├── gradebook.py          Оценки: выставление, история изменений, мини-дашборд студента
├── materials.py          Материалы курсов: ссылки на видео и ресурсы
├── submissions.py        Сдача работ студентом в виде ссылки (Google Drive и т. п.)
├── requierments.txt      Зависимости Python

├── docs/
│   ├── PROJECT.md        Этот файл
│   └── recovery-usability-test.md   Сценарий юзабилити-теста восстановления пароля
├── static/               Всё, что отдаётся браузеру
│   ├── index.html        Вся страница: разметка, стили, логика (JavaScript внутри)
│   ├── ui/theme.css      Новое оформление: цвета, темы, анимации (подключается после стилей из index.html)
│   ├── ui/ui.js          Анимации: скользящее выделение, смена темы, счётчики
│   ├── icons/            sprite.svg (все иконки), logo.svg, favicon.svg; *.jpg - старые растровые иконки, интерфейс их не использует
│   ├── media/            обложки курсов (webp, 320 и 640 px) и звук уведомления notify.mp3
│   └── map/              Карта университета: map.js, map.css, svg/ (15 планов этажей), LICENSE-aitumap.txt
├── tools/                Тесты и вспомогательные скрипты (не часть сайта)
│   ├── mock_server.py    Тестовый сервер с заглушками (см. раздел 1)
│   ├── test_*.py         Юнит-тесты
│   ├── reader_sim.py     Эмулятор NFC-считывателя
│   ├── build_map.mjs     Собирает svg-планы карты из tools/map_source/*.jsx
│   ├── gen_assets.py     Рисует обложки курсов и звук (нужен Pillow, ffmpeg)
```

Сервер раздаёт статические файлы **по явным маршрутам**, а не всю папку: `/` (index.html), `/icons/`, `/media/`, `/map/`, `/ui/`. Если добавляете новую папку со статикой, добавьте маршрут в `app_postgresql.py` (по образцу `ui_files`).

## 3. Как всё устроено

```
Браузер (static/index.html, JS) ──fetch /api/...──►  Flask (app_postgresql.py + модули) ──SQL──►  PostgreSQL
        ▲                                                   │
        └────────── HTML, CSS, JS, иконки, карта ◄──────────┘
```

- **Фронтенд** одностраничный. Вкладки переключаются без перезагрузки: функция `show(имя_вкладки)` рисует содержимое в `<main id="view">`. Все запросы идут через функцию `api(путь, параметры)`, которая добавляет заголовок `Authorization: <токен>` и разбирает JSON.
- **Бэкенд** отдаёт только JSON (кроме статики). Ошибки тоже JSON вида `{"error": "..."}`; для отказа внутри запроса используется исключение `Refuse(статус, сообщение)`.
- **Модули** `checkin.py`, `gradebook.py`, `materials.py`, `submissions.py` подключаются одинаково: `init_schema(cur)` (создать таблицы, вызывается из `init_db()`) и `register(app, ...)` (добавить маршруты, вызывается в конце `app_postgresql.py`). Это образец для новых функций.
- **Сессии** хранятся в памяти сервера: токен → (id пользователя, срок). Живут 2 часа, при перезапуске сервера сбрасываются.
- **Права проверяются на сервере**. Скрытие кнопок в интерфейсе удобство, а не защита.
- **База:** схема описана в `SCHEMA` (`app_postgresql.py`) и в `SCHEMA` модулей. Все `CREATE TABLE IF NOT EXISTS` и `ADD COLUMN IF NOT EXISTS`, поэтому запуск на существующей базе безопасен. Демо-данные создаются только если таблица пользователей пуста.

## 4. Роли и доступ

Роль приходит при входе (`role`: `student`, `teacher`, `admin`) и записывается в `document.body.dataset.role`. Какие пункты меню видны, решает CSS по атрибуту `data-r` у кнопки:

| Код `data-r` | Видят |
|---|---|
| `s` | студент |
| `t` | преподаватель |
| `st` | студент и преподаватель |
| `sa` | студент и администратор |
| `a`, `ad` | только администратор |
| (нет) | все роли |

| Пункт меню | Студент | Преподаватель | Админ |
|---|:-:|:-:|:-:|
| Dashboard | да | да | |

| Assignments | да | да | |
| Project groups | да | да | |
| Grades | да | да | |
| Applications | да | | да |
| Attendance | да | | |
| Check-in | да (ввод кода) | да (QR-код класса) | |
| Check-in readers | | | да |

## 5. Разделы сайта: что делают и где в коде

В колонке «Код» функция в `static/index.html`, если не указано другое.

| Раздел | Что делает | Код |
|---|---|---|
| **Вход** | Вход по почте и паролю, показ пароля. После 5 неверных попыток аккаунт блокируется на 20 минут. | `#signin`, `POST /api/login` |
| **Восстановление пароля** | 4 шага: запрос ссылки, проверка, новый пароль с индикатором надёжности, успех. Ссылка живёт 30 минут. Если письмо не приходит, форма обращения в поддержку. В демо-режиме «письмо» видно на `/demo-inbox`. | `recoveryRequestView`, `recoveryPasswordView` и др.; `/api/recover/*`, `/api/support-requests` |
| **Dashboard** | Студент: средний балл, число курсов и групп, таймлайн заданий (фильтр, сортировка, поиск), посещаемость, последние объявления. Преподаватель: сводка и дедлайны своих курсов. | ветка `dashboard` в `show()`; `GET /api/dashboard` |
| **My courses** | Карточки курсов. Нажатие на карточку открывает материалы этого курса. | ветка `courses`; `GET /api/courses` |
| **Media** | Материалы курсов: ссылки на видео и ресурсы. Студент смотрит, преподаватель добавляет в свои курсы, админ в любые. Видео YouTube и Vimeo играют на странице по кнопке «Play». | `showMedia()`; `materials.py` |
| **Schedule** | Недельное расписание по дням. Разовые занятия (с датой) создаёт админ. | ветка `schedule`; `GET /api/schedule` |
| **Assignments** | Студент: список заданий, статус, сдача работы ссылкой («Submit work», «Change», «Withdraw»). Преподаватель: создание и удаление заданий, счётчик сдач, кнопка «Grade». | ветка `assignments`; `/api/assignments`, `submissions.py` |
| **Grades** | Студент: мини-дашборд (средний балл, последние оценки с пометкой «Changed, was 7/10», разбивка по курсам). Преподаватель: журнал оценок по курсу и заданию, ссылка на работу студента, комментарий. | `showGrades()`; `gradebook.py` |
| **Project groups** | Преподаватель создаёт группы (2-6 человек) и добавляет студентов курса. Студент видит свою группу. | ветка `groups` (последняя в `show()`); `/api/groups` |
| **Applications** | Студент подаёт заявку (IROS, SSQI, SocGPA), может отозвать, пока она не рассмотрена. Админ рассматривает: одобрить или отклонить (при отказе нужна причина). | ветка `applications`; `/api/applications` |
| **Attendance** | Студент: посещаемость по курсам. | ветка `attendance`; `GET /api/attendance` |
| **Check-in** | Студент отмечается: карточкой на NFC-считывателе у аудитории или кодом из QR на экране преподавателя. Отметка открыта за 10 минут до пары и 15 минут после начала. Преподаватель видит QR своего класса (обновляется каждую минуту). | ветка `checkin`; `checkin.py`, `CHECKIN.md` |
| **Check-in readers** (админ) | Регистрация считывателей по аудиториям, привязка карт к студентам, журнал отметок (просмотр журнала записывается в аудит). | ветка `devices` |
| **Courses & schedule** (админ) | Создание и правка курсов (с несколькими преподавателями), добавление, правка и отмена занятий с датой. Проверка конфликтов по аудитории и преподавателю. | `showCourseAdmin()`; `/api/admin/*` |
| **Support requests** (админ) | Обращения из формы восстановления пароля, отметка «resolved». | ветка `support` |
| **Announcements** | Лента объявлений с поиском и категориями (General, Important, Exams, Events). Админ создаёт для всех, студентов, преподавателей или курса, может закреплять и ограничивать срок показа. Прочтение отслеживается, на иконке рейки счётчик непрочитанных. | `showAnnouncements()`; `/api/announcements*` |
| **University Map** | Интерактивные планы этажей корпуса C1 (3 этажа, блоки C1.1-C1.3), поиск аудитории, масштаб и перетаскивание, «Fun mode». Карта адаптирована из проекта aitumap (лицензия MIT). | `static/map/map.js`, `window.UniversityMap.mount()` |

## 6. Справочник API

Все пути начинаются с `/api`. Токен передаётся в заголовке `Authorization` (без слова Bearer). «любой» означает любой вошедший пользователь.

### Вход и поддержка
| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| POST | `/login` | все | вход: `{email, password}` → `{token, name, email, role}` |
| POST | `/logout` | вошедший | выход |
| POST | `/recover/request` | все | запросить ссылку восстановления |
| GET | `/recover/check` | все | проверить токен ссылки |
| POST | `/recover/reset` | все | задать новый пароль |
| POST | `/support-requests` | все | обращение в поддержку |
| GET | `/support-requests` | админ | список обращений |
| PATCH | `/support-requests/<id>` | админ | отметить обработанным |

### Курсы, задания, оценки
| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| GET | `/courses` | студент, преподаватель | свои курсы |
| GET | `/courses/<id>/students` | преподаватель курса | студенты курса и их группы |
| GET | `/assignments` | студент, преподаватель | задания (у студента со статусом сдачи, у преподавателя со счётчиками) |
| GET | `/assignment-types` | любой | типы заданий |
| POST | `/assignments` | преподаватель курса | создать задание |
| DELETE | `/assignments/<id>` | преподаватель курса | удалить (если нет оценок) |
| PUT | `/submissions` | студент | сдать или заменить ссылку на работу |
| DELETE | `/submissions/<assignment_id>` | студент | отозвать (пока нет оценки) |
| GET | `/courses/<id>/grades` | преподаватель курса | студенты, задания, оценки и сдачи |
| PUT | `/grades` | преподаватель курса | поставить или изменить оценку |
| DELETE | `/grades/<id>` | преподаватель курса | снять оценку (запись остаётся в истории) |
| GET | `/grades/details` | студент | оценки по курсам и последние события |
| GET | `/grades` | любой | устаревшее: сумма баллов по курсам (интерфейс не использует) |
| GET | `/dashboard` | студент, преподаватель | сводка |
| GET | `/attendance` | любой (отдаёт данные самого пользователя, у учителя и админа пусто) | посещаемость |

## 8. Фронтенд

### `static/index.html`
Один файл. Порядок внутри:
1. `<style>`: базовые стили и стили разделов (компактно, местами в одну строку).
2. `<link rel="stylesheet" href="ui/theme.css">`: **новое оформление**, перекрывает базовые стили.
3. Разметка: экран входа `#login`, экран восстановления `#recovery-shell`, приложение `#app` (рейка слева `.rail`, панель инструментов `.tools`, боковое меню `.side` с `.menu`, область содержимого `<main id="view">`).
4. `<script>`: вся логика.
5. `<script src="ui/ui.js" defer>`: анимации.

Главное в скрипте:

| Что | Где/как |
|---|---|
| `api(путь, опции)` | запрос к `/api` с токеном; при 401 возвращает на экран входа |
| `show(имя)` | роутер вкладок: цепочка `if/else if` по имени. Имена: `dashboard`, `courses`, `media`, `schedule`, `assignments`, `groups`, `grades`, `applications`, `attendance`, `checkin`, `devices`, `course-admin`, `support`, `announcements`, `map` |
| Большие разделы | отдельные функции: `showAnnouncements`, `showCourseAdmin`, `showMedia`, `showGrades` |
| Помощники | `esc()` (экранирование HTML, **обязательно для любых данных из API**), `card()`, `cover()`, `bar()`, `note()` (сообщение под заголовком), `opts()`, `fmtDate()`, `left()`, `ping()` (звук) |
| `act(действие, текст)` | внутри `show()`: выполнить действие, перерисовать вкладку и показать сообщение |
| Состояние | `sessionStorage`: `t` токен, `n` имя, `m` почта, `r` роль, `pc` код QR-отметки; `localStorage`: `theme` |
| Адрес API | если страница открыта не на порту 5000, запросы идут на `http://127.0.0.1:5000` (для Live Server на 5500 в сервере разрешён CORS) |

### Как добавить вкладку в интерфейс
1. В `.menu` добавить `<button data-v="имя" data-r="...">` с иконкой (если нужна роль, укажите код `data-r`).
2. В `show()` добавить ветку `v==="имя"` (или отдельную функцию, как `showMedia`).
3. Данные грузить через `api()`, вывод строить строкой HTML, все значения через `esc()`.
4. Выделение в меню и анимация появления работают автоматически (`show()` ставит класс `.on`).

### Карта (`static/map/`)
`map.js` подгружается при первом открытии вкладки Map, рисует планы из `map/svg/floor-<этаж>-<блок>.svg`. Планы генерируются командой `node tools/build_map.mjs` из исходников в `tools/map_source/` (*.jsx). Цвета карты задаются в `map.css` и подгоняются под тему в `theme.css`.

## 9. Оформление: темы, цвета, иконки, анимации

Всё новое оформление лежит в **`static/ui/theme.css`** (стили) и **`static/ui/ui.js`** (движение). Чтобы вернуть старый вид, достаточно убрать их подключение из `index.html`.

### Темы
Светлая тема по умолчанию, тёмная включается кнопкой внизу рейки (выбор запоминается в `localStorage`). Тема это атрибут `data-theme="dark"` на `<html>`. Цвета заданы переменными в начале `theme.css`:

| Переменная | Смысл |
|---|---|
| `--bg-grad`, `--bg` | фон страницы |
| `--side`, `--main`, `--card`, `--strip` | поверхности: боковая панель, основная область, карточки, нижняя полоса карточки |
| `--text`, `--muted` | основной и приглушённый текст |
| `--primary`, `--on-primary` | главные кнопки и акценты и цвет текста на них (при наведении кнопки меняются местами) |
| `--rail`, `--rail-fg`, `--rail-hover`, `--rail-pill`, `--rail-line` | левая рейка (в тёмной теме она светлая, это намеренная инверсия) |
| `--line` | тонкие границы |
| `--ok`, `--err` | успех и ошибка |
| `--sh`, `--sh-hover` | тени |

Палитра из референса: `#06141B #11212D #253745 #4A5C6A #9BA8AB #CCD0CF`. Чтобы сменить цвета сайта, правьте переменные в двух блоках: `:root` (светлая) и `:root[data-theme=dark]` (тёмная).

### Иконки
Все иконки это `static/icons/sprite.svg` (набор Lucide, лицензия ISC). Использование:
```html
<svg class="ico" aria-hidden="true" focusable="false"><use href="icons/sprite.svg?v=6#i-имя"/></svg>
```
Цвет иконки берётся из текста (`currentColor`). Чтобы добавить иконку, вставьте в `sprite.svg` `<symbol id="i-новая" viewBox="0 0 24 24">...</symbol>` и **увеличьте `?v=` во всех ссылках** на спрайт, иначе браузер покажет старую версию из кэша.

### Анимации (`ui.js` и `theme.css`)
- Скользящее выделение пункта в меню и рейке (`.nav-pill`): `ui.js` ставит его под активную кнопку.
- Плавная смена темы (View Transitions API, если браузер умеет).
- Заголовки групп меню (Learning, Attendance, Administration) скрываются, если у роли нет пунктов в группе.
- Числа на дашборде «отсчитываются» от нуля.
- Появление страниц и карточек, подъём карточек при наведении, кнопки слегка растут и инвертируют цвета.
- При включённом в системе «уменьшить движение» анимации отключаются.

### Адаптивность
Порог 760 px: рейка и инструменты ложатся в строку, меню прокручивается по горизонтали, подсказки и заголовки групп скрываются.

## 10. Безопасность

- **Пароли:** bcrypt с индивидуальной солью. Проверка пароля выполняется всегда, даже если почты нет, чтобы нельзя было узнать, существует ли аккаунт.
- **Блокировка входа:** 5 неудачных попыток подряд, блокировка на 20 минут. Счётчики в памяти сервера.
- **Сессии:** случайный токен, 2 часа, в памяти сервера.
- **Права:** на каждом маршруте проверяется роль и принадлежность курса (`guard()`, `teacher_guard()`, `admin_guard()`, проверка `course_teachers`).
- **Восстановление пароля:** в базе только SHA-256 токена, ссылка живёт 30 минут и одноразовая, ограничение частоты запросов, ответ не выдаёт, существует ли почта.
- **Check-in:** карты хранятся как HMAC-хэш, ключи считывателей как SHA-256, QR-код живёт 60 секунд и подписан, ограничение 60 запросов в минуту.
- **Ссылки (материалы, сдача работ):** принимаются только `http` и `https`, до 500 символов, без пробелов, кавычек и `<>`. Плеер YouTube/Vimeo строится только из извлечённого идентификатора видео, во фрейме включена изоляция `sandbox`, внешнее содержимое подгружается только после нажатия «Play». Ссылки открываются с `rel="noopener noreferrer"`.
- **Вывод данных:** любые значения из API в интерфейсе проходят через `esc()`.
- **Ошибки:** сервер отвечает JSON без внутренних деталей.

## 13. Как добавить новую функцию

Образец: `materials.py` (маленький) и `gradebook.py` (с историей).

1. **Новый файл** `имя.py` с тремя частями:
   - `SCHEMA` и `init_schema(cur)`: таблицы (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`);
   - `register(app, *, db, query_one, rows, guard, Refuse, ...)`: маршруты через `@app.get/post/put/delete`.
2. **Подключить** в `app_postgresql.py` тремя строками: `import имя`, `имя.init_schema(cur)` в `init_db()`, `имя.register(...)` перед `if __name__ == "__main__"`. Функции передаются через `lambda`, чтобы тесты могли их подменять.
3. **Права:** в начале каждого маршрута `guard()` (любой вошедший) или `teacher_guard()` / `admin_guard()`; принадлежность курса проверять через `course_teachers`; ошибки через `raise Refuse(статус, "сообщение")`.
4. **Ввод:** всё валидировать на сервере (типы, длины, диапазоны), ссылки пропускать через `materials.clean_url`.
5. **Интерфейс:** вкладка по инструкции из раздела 8, стили добавить в `theme.css`.
6. **Тесты:** файл `tools/test_имя.py` по образцу `test_materials.py`; для просмотра интерфейса добавить заглушки в `tools/mock_server.py`.

## 14. Известные ограничения

- **Сессии и счётчики входа в памяти процесса:** после перезапуска сервера все выходят из системы; несколько процессов сервера не поддерживаются.
- **Демо-режим:** общий демо-пароль, демо-«почта» восстановления. В настоящей эксплуатации выключить (`APP_ENV=production`) и подключить настоящую отправку почты.
- **Несколько преподавателей курса:** задания, оценки, материалы, расписание и сдачи учитывают всех преподавателей через `course_teachers`. Но часть старых запросов (список проектных групп, удаление группы, сводка дашборда, расписание в части имени преподавателя) использует поле `courses.teacher_id`, то есть первого преподавателя. Второй преподаватель курса может не видеть эти данные. При доработке заменить на `course_teachers`.
- **Запись студентов на курс:** в интерфейсе нет экрана, только демо-данные. Новым студентам записи в `enrollments` нужно добавлять вручную.
- **Файлы не загружаются:** работы и материалы только ссылки.
- **Уведомлений о новых оценках и сдачах нет:** преподаватель видит сдачи в Grades и по счётчику, студент оценки в Grades.
- **Проверка на настоящей базе:** юнит-тесты и тестовый сервер не выполняют SQL. После изменений запросов запускайте приложение на PostgreSQL и проходите все роли вручную.
- **Шрифт Inter** отдельно не подключён, используется системный шрифт.
- **Устаревшее:** `GET /api/grades` (сумма по курсу) и `POST /api/schedule` (недельные занятия) оставлены для совместимости; растровые иконки `static/icons/*.jpg` не используются.
